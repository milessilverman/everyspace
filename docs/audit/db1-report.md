## Other changes and risks

The old blanket "grant all to authenticated" after migrations was removed, so a migration's REVOKEs now take effect in tests, as they do in production. New helpers: `as(db, user, fn)` and `freshDb({pause})` (seeds legacy data mid-replay to prove the backfill).

## M5 (DB-2): availability engine, `20261124050000_availability.sql` (local staging only)
Status: done. `cd platform && npm test` 204 pass / 0 fail (+10 `availability`, +36 `availability_parity`, +3 rls tables). `npm run test:staging` 12 pass / 0 fail (5 + 7 race, run 3x). `node --test core/tests/*.test.mjs` 236 pass (+40); repo-root command with `tests/*.test.mjs` 251 pass. Nothing ran against the hosted project.
- Added: tables `space_relations, resources, space_resources` (RLS read = property.read, write = space.write; same-property triggers, incl. moving a space/resource); `spaces.setup_minutes/cleanup_minutes`, `reservations.exclusive`, `calendar_imports.consecutive_failures/last_ok_at`; functions `blocking_spaces, availability_conflicts, create_booking, import_reservations, can_book, can_read_bookings, conflict_pairs`, trigger `track_import_health`; view `sync_health` (security_invoker); constraint `reservations_exclusive_no_overlap` (btree_gist); `place_hold` and `detect_conflicts` rebuilt on `availability_conflicts` (same signatures). JS mirror `core/availability.js` (`findConflicts, blockingSpaces, isAvailable`), 35 shared cases in `core/tests/fixtures/availability-cases.js`; the parity test compares SQL and JS row by row (kind, ids, order, detail).
- Test edits: `rls.test.mjs` only (3 TENANT entries; `reservations.owner: false`). No other test inserted reservations as `authenticated`, so none changed. Host Console only reads `reservations` (grep), so revoking direct writes breaks nothing there.
- Deviation: `symmetric` is a reserved word in Postgres. The column keeps the spec name but raw SQL must quote it (`"symmetric"`); PostgREST quotes for you.
- Deviation: `place_hold` now also uses the shared rules and the new caller check (relations, resources, buffers; audit finding 5). `mark_hold_safe` still uses `busy_count` (family + quantity only).
- Deviation: the write policies on `reservations` were dropped as well as the privileges revoked. `track_import_health` keeps the two new `calendar_imports` columns right from today's calendar-sync writes (`last_status`), and it stands aside when a writer sets `consecutive_failures` itself. `last_ok_at` is backfilled from `last_synced_at` where the last status was ok.
- Semantics kept from the old `detect_conflicts`: `block` rows never conflict, and conflicts on stays that ended more than a day ago are left as they were. Capacity and resource conflicts are recorded as pairs, because `conflicts` is pairwise. The `conflicts` list from `import_reservations` leaves out blocks and holds on the same site (`settle_holds` links those).
- Caller identity comes from `current_setting('role')`: `service_role` is allowed, `authenticated` needs `booking.write`, and a superuser session with no role set is allowed. `auth.uid() is null` is never trusted. An API role cannot change that setting.
- Limit: the exclusion constraint covers only same-space, quantity-1, raw-range rows written by `create_booking`. Family, relations, resources, buffers, holds and capacity rely on `lock_property` + `availability_conflicts`, and only on the RPC path.
- Limit: service-role writers that bypass the RPCs (calendar-sync's direct upsert) are flagged afterwards by `detect_conflicts`, not stopped.
- Limit: the shared PGlite helper has no btree_gist, so the constraint is skipped there. `availability.test.mjs` loads btree_gist itself, so the constraint is tested on PGlite and on PG16.
- Limit: relations are not transitive and are not inherited by parents or children. "Directional" means an existing booking on B does not stop a new booking on A.
- Limit: the JS mirror takes only live holds, because it never reads `now`. Lock safety assumes READ COMMITTED (the PostgREST default).
- Limit: there is no RPC for a signed-in user to edit or cancel an Everyspace booking (only `import_reservations` with the same channel and uid).
- Owner approval before production (A2): btree_gist on the hosted project (created in `extensions`). Confirm that hosted PostgREST sets the `role` setting (on hosted Supabase `postgres` is not a superuser, so SQL-editor or pg_cron calls must `set role service_role`). Confirm the directional-relation meaning. Add a cancel/edit RPC before hosts need one.

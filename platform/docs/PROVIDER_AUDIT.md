# Provider integration audit

Verified November 20, 2026 UTC using public provider materials. **High** means the cited material directly documents the stated product or workflow. **Medium** means the material documents an adjacent workflow or leaves the direction, scope, or eligibility unclear. **Unverified** means Everyspace has no confirmed contract or public evidence for that capability. Confidence applies to the cited feature. It does not establish an active integration.

Calendar directions are from the provider's perspective. **In** means it reads a compatible external feed. **Out** means it publishes an iCal export. A provider may limit feature eligibility, time granularity, upstream hosts, and refresh intervals. **API off** applies to all 22 platforms in this draft. Approved partner actions would still need listing authorization, provider-specific sandbox and security validation, and an independent release decision per operation. Everyspace's forwarded-message intake uses host-submitted messages for review.

## Swimply strategy

Swimply documents iCal import delays of several hours and export updates taking up to 24 hours to appear in an external calendar. Its Cronofy flow uses the Swimply website and can publish bookings with the host’s buffer. Treat both as observations of calendar occupancy. Booking decisions, transaction ordering, payouts and guest messages need separate evidence and permissions. [Swimply calendar setup](https://swimply.zendesk.com/hc/en-us/articles/30133735282451-Syncing-Calendar)

1. **Validate the supported workflow for one pool.** With an opted-in host, create a Swimply pool child space under the Airbnb whole-property space. Put independent parking in a separate space. Configure the actual property time zone, one unit for an exclusive pool, and host-selected cleanup time. Connect each documented iCal direction only after checking the exact live feed hostname and verifying both imported and exported dates in the two dashboards. Use a controlled hold, an unrelated driveway, a daytime interval inside an overnight stay, cleanup neighbors, and a date crossing daylight saving. Record event formatting, time granularity, whether imported blocks are mirrored, and elapsed times for creation, changes, and removal. [Swimply calendar setup](https://swimply.zendesk.com/hc/en-us/articles/30133735282451-Syncing-Calendar)
2. **Capture confirmations and changes with consent.** Collect redacted examples of new requests, confirmations, accepted changes, pending extension requests, cancellation, and refunds from an opted-in host. Record which notice carries a stable booking code, precise duration, and time zone. The intake should populate review and help the host find the original booking. Everyspace can record an accepted extension and show related-space conflicts. A pending extension or refund notice alone leaves occupancy unchanged. Swimply's host interface has separate extension approval and payout/refund behavior. [Host Bookings tab](https://swimply.zendesk.com/hc/en-us/articles/30336709800083-How-To-Navigate-the-Bookings-Tab) · [Booking edits](https://swimply.zendesk.com/hc/en-us/articles/54093602547475-Booking-Edit-Requests) · [Refunds](https://swimply.zendesk.com/hc/en-us/articles/31127196235539-Refunds)
3. **Evaluate a dedicated calendar with Cronofy.** Ask Swimply and Cronofy whether an opted-in, dedicated listing calendar is an approved path for Everyspace to observe changes. Prefer free/busy data if it meets the pilot needs. Verify connection consent and scope, webhook signatures, replay, event identity, buffer duplication, latency, revocation and pricing before building. Use a calendar dedicated to this listing to avoid collecting personal calendar data. [Calendar access modes](https://docs.cronofy.com/developers/authorization/access-modes/) · [Calendar webhook verification](https://docs.cronofy.com/developers/push-notifications/) · [API pricing](https://www.cronofy.com/api-pricing)
4. **Ask for an explicit partner path.** Use Swimply Support to request a product or partnership owner. Describe the single-pool pilot and ask whether they offer sanctioned partner feeds, read-only booking and lifecycle events, or a direct booking and availability contract. Ask for the scopes, host consent, inventory model, event revision ordering, retries, signatures, cancellation and refund semantics, messaging policy, rate and concurrency limits, sandbox fixtures, certification, and costs. Get written permission for each requested operation. [Swimply Support](https://swimply.zendesk.com/hc/en-us/requests/new) · [Terms](https://swimply.com/termsandconditions)
5. **Release authorized reads before writes.** Add read-only events, exact listing and booking mapping, replay deduplication, durable recovery and comparison against the host dashboard. If a provider contract can guarantee exclusive inventory at commit time, test that property-level interlock through retry and timeout scenarios before releasing any operation that accepts, changes, cancels or messages about a booking. If the contract cannot protect both providers at commit time, limit release to ingestion, alerts, and verified manual decisions.

## Founder involvement

- Invite and authorize a pilot host for each first-wave provider. Obtain permission to use their calendar links and redacted messages in a staging environment. Set the property relationships, units, cleanup times, and which site can confirm independently.
- Contact Swimply via the route above. Request Airbnb Homes Connectivity through [Airbnb Partner Support](https://www.airbnb.com/partner/support) and Vrbo supply access through the vendor address published by [Integration Central](https://integration-central.vrbo.com/t). Check [Booking.com onboarding](https://connect.booking.com/) before submitting.
- Decide whether to approve an inbound email transport and a dedicated calendar trial. Confirm consent and permissions, and review any mail, calendar or partner fees before enabling either service.
- Review the staged migration and rollback plan, the host-facing provider checks, and the proposed pilot limits before authorizing a deployment.
